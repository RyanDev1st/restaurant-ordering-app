# Report guideline (condensed from teacher's "JavaOOP - Report Content Guideline.docx")

Format: Times New Roman 13, justified. Code pasted keeps its original colours; paste only useful code,
otherwise give the file path. Every table or figure needs at least one paragraph discussing it.

| Section | Must contain |
| --- | --- |
| Versions, abbreviations, lists of figures / tables, TOC | front matter |
| I. Introduction | business requirements as the customer; function list; 1 user role table; 1 use case diagram |
| II. Class analysis | objects table (name, state, behaviours); classes per group; inheritance + abstract classes diagram (no types / params yet) |
| III. Class design | class diagram; class table (variables, methods, modifier + why); abstract class table; overloading; overriding; inheritance code; 3-tier model; package design; interface design; data + method access control tables |
| Encapsulation vs inheritance vs polymorphism | one code sample from our project for each, with why |
| Experiment | environment (PCs, CPU, RAM); tools + install appendix if new; function table; database (min 4 tables, ERD, 5-7 classes, max 10); GUI (table of screens in order, min 4 figures, each button and its event explained) |
| Conclusion | honest pros / cons, self-score with reason, future features |
| Duty roster | ID, task, in charge, start, end, state, note |
| Reference, Appendix A | sources; class descriptions with source path |
